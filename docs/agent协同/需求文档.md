# 背景说明

当前，数据要素正成为数字经济高质量发展的核心生产要素，数据要素流通、合规交易与价值释放已经成为数字产业的重要发展方向。在数据要素市场的实践中，大量有价值的数据资源分散沉淀在各类主体的个人与企业网盘之中：业务台账、实验记录、行业报表、归档文档、结构化数据表等文件分散存储，具备潜在的数据要素价值，但长期处于 “沉睡” 状态，难以被快速识别、归集与供给。

一方面，数据需求方（企业、研究机构等）常以悬赏的形式发布数据要素需求，明确业务场景、数据字段、时间范围、格式与合规约束，希望快速获取匹配的数据源；另一方面，网盘持有用户拥有海量自有文件，却缺少自动化手段，无法快速判断自己存储的文件是否契合悬赏需求。依靠人工逐条翻阅、核对文件，存在效率低、漏检率高、核查成本大的痛点，同时还容易忽略隐私、版权、保密等合规风险。

传统网盘仅提供存储、检索、分类能力，大多依赖关键词检索或简单元数据过滤，无法理解悬赏需求的语义意图，也不能自动校验文件内部字段、评估数据质量与合规风险，难以支撑数据要素悬赏匹配这类智能化场景。

在此背景下，引入智能 Agent 对网盘文件进行分层扫描、语义理解与自动评估，能够打通 “数据要素悬赏发布 — 网盘文件智能匹配 — 风险校验推荐” 的链路：Agent 在用户授权范围内，对网盘索引进行分级检索、内容解析、字段核验与合规研判，自动筛选潜在符合悬赏要求的文件，生成带证据与风险提示的推荐清单，交由用户人工复核确认后再开展后续脱敏、交付流通。该方案可以盘活网盘内沉睡的数据资源，降低数据供需双方的对接成本，在守住数据安全与隐私合规底线的前提下，探索网盘场景下数据要素价值挖掘与流通的新模式。

# 项目说明
## 1. 项目名称
基于智能Agent的网盘数据要素悬赏文件匹配演示Demo

## 2. 项目定位
本项目为**小型验证Demo**，核心目标是**验证智能Agent在网盘场景下，自动根据企业数据要素悬赏需求筛选、评估、推荐用户网盘文件这一方案的可行性**。
> 网盘基础底座【已开发完成】，本次开发重心不重复建设网盘存储能力；全部新增开发重心聚焦于「Agent分层扫描、语义解析、匹配推理、合规风险评估、证据化推荐、悬赏管理链路」，用来证明该智能匹配流程可以正常闭环。

## 3. 项目背景
数据要素已经成为数字经济关键生产要素，不少需求方通过悬赏方式定向征集特定数据集。大量具备潜在价值的数据沉淀在用户网盘内，但传统网盘只提供存储、关键词检索能力，用户只能人工翻阅核对文件，效率低下，且难以同时校验字段完整性、时间范围、隐私合规风险。
本Demo旨在验证：在用户授权前提下，Agent可以自动解读悬赏需求、分层扫描网盘资源、输出可解释的候选文件推荐，降低数据供需对接成本。

##### 存储路径推演（无需入库）
> 正式文件: {storage_root}/{sha256[0:2]}/{sha256[2:4]}/{sha256}     # 前4位分目录，防单目录过多
> 临时分片: {temp_root}/{task_id}/{chunk_index}                     # 分片上传临时目录，合并后删除

##### 分片流程
> 分片上传 → {temp_root}/{task_id}/{0..n-1}
> 全部完成 → 按序合并 → 计算 sha256 → 写入 {storage_root}/xx/yy/{sha256}
>         → 若 file_meta 已存在则秒传；否则 insert file_meta
>         → 删临时目录，update user_file / used_size

## 4.4 本次新增开发模块（Demo核心验证部分）
> 角色沿用：普通个人用户、企业需求用户、管理员（企业用户本质为user表中增加角色标记，不新建独立用户表）
### 4.4.1 企业悬赏管理模块
企业用户登录后，可发布、编辑、停用自己的数据要素悬赏需求：
- 录入自然语言悬赏描述：目标数据内容、必填字段、时间约束、支持文件格式、禁止内容、合规限制
- 系统自动调用LLM将自然语言悬赏解析为结构化需求对象，存入数据库
- 查看悬赏基础状态、查看该悬赏下所有个人用户提交的匹配汇总统计
> 重要约束：企业**无法直接访问、下载个人原始网盘文件**，仅能看到匹配概览；原始文件、匹配证据只对所属个人用户可见。

### 4.4.2 智能Agent核心模块（本次开发重点）
Agent为独立任务调度链路，接收悬赏任务，**严格在个人用户授权的扫描范围之内**执行分层扫描匹配：
1. 悬赏结构化解析：LLM将企业自然语言悬赏，解析为结构化需求对象（业务领域、必填字段、时间约束、格式、禁含敏感内容等）
2. 元数据粗筛：读取user_file、file_meta元数据，快速过滤明显无关、回收站内文件
3. 向量语义召回：读取已预解析的文件文本摘要向量，向量检索召回Top-K候选文件
4. 候选文件深度解析：对召回文件读取磁盘原始文件，调用解析工具
   - 图片：OCR文字识别 + 图像内容描述
   - PDF/Word/TXT：提取全文文本
   - Excel：读取表头、抽样单元格内容
   > 复杂格式、加密文件直接标记解析失败，跳过
5. 推理评估：LLM综合解析内容与结构化悬赏需求，判定匹配等级、抽取匹配证据片段、识别隐私/敏感信息风险
6. 结果持久化：生成标准化推荐清单，存储匹配等级、原文证据、风险告警、复核建议
7. 审计留痕：记录本次扫描任务范围、扫描文件列表、推理结果、操作人，全程可审计

> 硬性约束：Agent仅做推荐辅助，**不会自动提交、自动对外分发文件**；所有候选结果仅推送给文件所属个人用户，由用户人工复核、脱敏后再决定是否交付。

### 4.4.3 个人用户授权 & 复核交互模块
个人用户侧新增页面能力：

- 查看Agent返回的推荐报告、匹配证据片段、敏感风险提示

### 4.4.4 管理员扩展能力（在已有后台上增加页面）

## 5. 项目边界与约束（重要，明确是Demo）
1. 定位为可行性验证原型，**非商用产品**，不面向真实大规模数据要素流通场景；
2. 本次不改造底层网盘存储，不做分布式存储、高并发、海量文件支持；分片上传底座已稳定，不再优化性能；
3. Agent安全机制以演示为主，敏感信息检测 = 关键词规则 + LLM辅助识别，不达到等保、正式数据流通平台合规标准；
4. 数据交付链路仅在界面做流程示意，**不对接真实数据要素交易平台、不上链、不实现正式确权与资金结算**；
5. 所有Agent扫描动作必须经过用户主动勾选授权，全流程写入审计日志，用户随时可查看扫描范围和记录；
6. 文件解析仅支持常规图片、PDF、docx、txt、xlsx；加密文件、压缩包、特殊格式Demo直接跳过，不实现解压嵌套扫描。

## 6. 预期验证目标（项目验收核心）
基于已有的网盘底座，新增模块跑通完整业务闭环：
企业用户发布一条数据要素悬赏 → Agent解析悬赏为结构化需求 → 个人用户选定文件夹授权扫描 → Agent在授权范围内分层扫描、解析文件真实内容、语义推理、风险识别 → 输出分级推荐清单（附带证据、风险提示）→ 用户查看、人工复核候选文件。
**证明：基于Agent的网盘文件智能悬赏匹配流程逻辑自洽、可落地，该方案具备可行性。**
